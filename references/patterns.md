## 零、三条通用铁律（比选对图型更重要）

**1. 强调预算 = 恰好 2 个元素，且动手前就点名是哪两个。**
不是"绿色少用"，是"这张图里只有 A 和 B 是绿的，其余全中性"。画之前先写下 A 和 B 是什么。
绿色给到第 3 个元素 = 信号归零。每种范式下面都写了它的 2 个 accent 该给谁。

**2. 9 个节点是上限，密度目标 4/10。**
超过 9 个主节点，大概率是两张图。超预算时**聚合成一个带计数的节点**（如"其余 6 项"），
**不要静默删节点**——聚合了要在图上或回复里说一句。

**3. 删除测试：每个节点、每条线、每个标签都要能过一句"删了会丢什么信息"。**
- 两个总是一起出现的节点 = 一个节点。
- 关系已经能从位置看出来的连线 = 删掉。
- 颜色或形状已经表达的标签 = 删掉（例：箭头只能朝右，就别再写"向右演进"）。

## 一、状态机（单据状态流转）

**用在**：转移单、SAN 管控单、公示期、成长期毕业、冻结/解冻——**凡是 PRD 里写"状态"的都该画这个**，比文字表格清楚。

**画法**：状态用圆角矩形（rx 8）。起点一个实心圆点，终点一个套环圆点。转移箭头上必须写
`触发事件 [守卫条件] / 动作`（用不到的段省略）。自环画在状态上方。沿主流向排（左→右或上→下），
宁可重排也不要让箭头交叉。

**硬上限**：转移数 > 状态数 × 2 → 这是两个状态机，拆。

**2 个 accent**：终态里最该被看到的那一个（通常是异常态或 happy completion），加它的入边。

**最容易犯的错**：
- **箭头不写触发条件**——状态机的全部价值就是"什么事件让它跳的"，不写等于没画。
- 把"任意状态超时→失败"从每个状态都画一根线。改成一条独立注记：`* → 失效（72 小时）`。

## 二、泳道（跨角色流程）

**用在**：客户迁移、合同变更、账号注销——**一个流程里有 3 个以上角色在互相交接**时用它。

**画法**：横向泳道，一道一个角色（代理商 / 商户 / 销售 / 平台后台），左侧留白写角色名。
泳道分隔线用 1px 细线。步骤矩形放在**执行它的那个角色的道里**，箭头表示流转。

**硬上限**：泳道 ≤ 5 道。不要求每道步骤数相等，一道只有一步也正常。

**2 个 accent**：**跨道的那根交接箭头**——耦合最重或最容易卡住的那一次交接。交接才是泳道图存在的理由，
不是步骤。

**最容易犯的错**：
- 一个步骤横跨两条道（说明责任没定清，挑一个 owner）。
- 箭头来回蛇形穿道——重排步骤顺序，让主流向基本是直的。
- **想画"谁负责什么"却画了泳道**：那是组织/职责图，泳道解释的是过程不是归属。

## 三、故事地图（分期规划 + 发版切割线）

**用在**：1 期 / 2 期 / 3 期怎么切——**这是他手上最契合的一张，目前没有对应范式**。

**画法**：三段竖着摞。
1. **骨干**：≤5 个活动，按用户经历的**叙事顺序**从左到右排（不是优先级顺序），宽卡片。
2. **行走骨架**：每个活动下面挂它的用户步骤，小卡片。
3. **发版切片**：横向色带，每带一个左侧标签（`1 期` / `2 期` / `以后`）。故事卡按所属活动列对齐落进带里。
4. **发版切割线**：MVP 带正下方一条通栏绿线 + 右端标"本期切线"。

**硬上限**：≤5 活动 · ≤3 切片 · ≤12 张故事卡 · 每片 ≤4 张。

**2 个 accent**：切割线（算一个）+ 风险最高的那一张故事卡（虚线描边 + "风险"小标签，算另一个）。

**最容易犯的错**：
- **没有切割线**——那就只是个网格状 backlog，切线是这张图的全部意义。
- 列按优先级排而不是叙事顺序。
- 切片按日期命名（`Q3`/`Q4`）——排期一滑名字就错，按范围命名（`1 期`/`2 期`/`以后`）。
- **和看板 / 用户旅程混了**：看板的列是**状态**、没有叙事顺序也没得切；旅程有**情绪曲线**；
  故事地图两样都没有，它的列是叙事、行是发版。

## 四、鱼骨（多因归一果）

**用在**：归因分析——"代理商佣金为什么跌"、"某指标为什么异常"。它展示的是**查过什么**，不只是结论。

**画法**：横向主脊线从左到右，右端箭头指进一个"现象框"。类别骨线按固定 60° 斜插在主脊上、上下交替，
外端挂类别名小标签。子原因是骨线上的短横刺 + 标签。

**硬上限**：类别（骨）≤5 根 · 每根子原因 ≤3 条 · 总子原因 ≤18。

**2 个 accent**：**确认的那一根根因骨（骨线 + 类别标签算一个）+ 现象框**。就这两处。

**最容易犯的错**：
- **两根骨都标成根因**——那是两张图，或者根因还没找到。
- 一根骨挂零个子原因：空类别是占位符不是发现，删掉。
- 子原因在复述类别名（"部署"骨下挂"部署问题"）。
- **拿鱼骨画一串按时间发生的故障**——那是时间轴。鱼骨是**一个**结果的多个原因，不是时序。
- 套 6M 模板（人机料法环测）留一堆空类别——类别名要来自这次实际查的东西。

## 五、象限（二维定位 / 优先级）

**用在**：优先级（影响 × 成本）、分层定位、四种战略选项。

**画法**：2×2，中心十字轴 1px。**轴标签只写一个词**，放在箭头尖外侧，不要压在轴线上，
不要加"高/低"、不要加箭头符号、不要写在中点。项目用小圆点 + 标签，标签离点 8–10px 且不跨轴线。

**硬上限**：≤12 项，超了就聚类或拆图。

**2 个 accent**：右上角那一个"先做"项，最多再加它的标签。

**两种变体，别混**：
- **标准象限**：格子里是**定位的点**，点在格子里的具体位置有意义。
- **战略矩阵**（咨询那种）：格子里是**命名的场景 + 1–3 行描述**，位置本身无意义，
  强调色给**一整个格子**而不是一个点。位置有意义就用标准象限。

**最容易犯的错**：
- 四个格子填四种颜色——位置和标签已经做完了活，颜色只是噪音。
- 点正好落在轴线上（归哪个象限？）。
- 轴没名字。

## 六、依赖图（扇入与环）

**用在**：需求之间的依赖、系统模块依赖。**只有当数据里真的存在这两样时才用它**：
① 一个节点有多个父（多处汇聚到同一个依赖）② 存在环。
两样都没有（每个节点恰好一个父、没有回指）→ **用骨架图/树，别硬套依赖图**，并且要说出来。

**画法**：按依赖深度分横排层，第 0 层（没人依赖它的入口）在顶，越深越下。
正向边向下跨层。每个节点右上角挂一个**扇入徽章**（"4 入" = 有 4 个节点依赖我）。

**硬上限**：≤9 节点 · ≤14 条边 · ≤4 层 · 最多标 1 个环。
超预算：把叶子簇聚合成一个带计数的节点（"+6 个叶子"），并说明。

**2 个 accent**：**那条回指的环边 + 它的"环"标签**。环两端的节点本身不上色，否则预算花错地方。

**最容易犯的错**：
- **没有扇入徽章**——看不出依赖集中在哪，那这张图就没有比树多任何东西。
- 一团乱麻不分层——分层是它可读的原因，不是收尾抛光。
- 标了两个环——挑最重要的那个，第二个会把第一个的信号吃掉。

## 七、甘特（排期）

**用在**：上线节奏（1 期 9/3、2 期 10/22–29、3 期 11/1）、并行轨道、里程碑先后。

**画法**：左侧标签列放任务名 + 阶段眉标，右侧时间区从左到右。每行一条 bar。
阶段分组用一层极淡的底色区块 + 左上角眉标。可选一条"今天"竖虚线。

**硬上限**：≤12 个任务（超了就折叠成阶段级视图）· 每阶段并行轨 ≤5 条。

**2 个 accent**：关键交付物 / 关键路径上那**一条** bar。

**最容易犯的错**：
- 所有 bar 一样重——焦点 bar 必须跳出来。
- 第一版就画任务间的依赖箭头（先别画，真需要再加）。
- 把起止日期写进 bar 标签里（日期归时间轴）。

## 八、漏斗 / 金字塔（转化与分层）

**用在**：转化流失、分层人数分布、重要性排序。

**画法**：4–6 层梯形。**金字塔尖朝上**（尖 = 最少/最珍贵，底 = 基础）；**漏斗尖朝下**（窄端 = 转化下来的）。
一张图里不要混两种朝向。

**关键**：**宽度必须诚实**——按真实数量/百分比成比例，不要为了好看做成等差。漏斗右侧标流失率（`−40%`）。

**硬上限**：≤6 层，7 层以上必须压缩或拆。

**2 个 accent**：只给**一层**——金字塔的尖、漏斗的转化层、或瓶颈层。给底层等于稀释"尖=稀缺"的信号。

---

## 九、时间轴（事件序列）

**用在**：政策演进、事故复盘时间线、版本历史。

**画法**：横向细基线 + 刻度 + 日期标签。事件是基线上的小圆点，标签**上下交替**避免撞车，用细引线连回圆点。
重要里程碑用绿色大一号的点。

**关键**：**间距必须诚实**——时间间隔不等就不要等距摆点。某段太密就把轴**可见地断开**，别偷偷压缩。

**最容易犯的错**：把不等距的事件等距摆；缺单位标注；标签不做上下错位导致糊成一片。

## 十、用户旅程（有情绪才用）

**用在**：用户/商户在某段体验里做了什么、感受如何。**情绪曲线是它的承重墙**——
**如果每个阶段感受都一样、或你说不出每阶段的感受，就别用它，改用路线图或流程图。**

**画法**：竖着摞。
1. **阶段头**：≤6 个等宽列。
2. **情绪带**：3 条水平参考线标 `高 / 中 / 低`，一条折线穿过每阶段一个点，情绪值只取 5 个**有名字的档**
   （高/中高/中/中低/低），**不要用 0–100 打分**。谷底那个点和它的入段线上绿。
3. **内容行**：≤3 行——`动作`（他做了什么）、`触点`（在哪个界面/渠道），可选第三行放指标或负责人。
4. **痛点标记**：只在谷底打，最多 2 个，虚线小标签写清是什么摩擦。

**硬上限**：≤6 阶段 · ≤3 内容行 · ≤2 痛点 · 一张图只画一个角色。

**2 个 accent**：谷底点 + 它的入段线（算一个），痛点标记（算另一个）。

**最容易犯的错**：
- 没有情绪曲线（那是流程图）。
- **用 emoji 当情绪标记**——飞书画板 SVG 文字里放 emoji 会静默断图，而且 emoji 不打印、小字号看不清。
  用命名档位 + 参考线。
- 一张图叠两个角色的曲线（两条都读不出来），一角色一张。
- 每个阶段都打痛点标记 = 没有焦点。

## 附：抄过来时**不要**跟着抄的东西

原库是给浏览器 HTML 用的，这几样和飞书画板直接冲突，已在上面剥掉，别从原文回抄：

1. **字号**：原库大量用 8–9px（Geist Mono 眉标）。**飞书画板下限是 13px 整数**，低于它线上会折行，
   而且本地 PNG 和 `--check` 都发现不了。原文里所有"小眉标"到这边一律 13px 起，放不下就缩短文案或加宽容器。
2. **强调色**：原库是 coral `#eb6c36`，我们只用主绿 `#10A37F`。
3. **字体**：原库指定 Geist / Instrument Serif / Geist Mono，**画板不设 `font-family`**。
4. **暖底 + 点阵背景 + 三变体（浅/深/全编辑体）**：不要。页底 `#FAFBFB`、卡面白，一版就够。
5. **斜线/曲线**：鱼骨的 60° 骨线、旅程的情绪折线、Wardley 的依赖线是它们的定义性语法，可以用；
   **其余所有连接线仍走 `marker-end` 原生连接器的直角折线**，不要手画三角。

## 附：自定义列布局的右边界

`geist_layout.py` 的 `W = 1680`，而 `head()` / `strip()` 画的是 `x=40, width=W-80` → **右边界在 1640**。
自己排多列网格（故事地图、泳道、甘特、象限）时，**最右一列的 `x + 列宽` 必须 ≤ 1640**，
否则卡片会戳出标题条和底色带——`--check` 会报成 `node-overlap`，但看报错信息完全猜不到是"列宽算超了"。
2026-08-24 画三期故事地图时踩过：5 列 × 284 + 4 × 20 起点 160 → 1660，超 20px。
